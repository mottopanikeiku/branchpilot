Adaptive inference control plane

Adaptive inference control, prompt by prompt.

BranchPilot observes each completed model sample, applies a deployable stopping strategy, then either requests exactly one more sample or stops. Fixed counts, transparent heuristics, and learned Safetensors policies share the same bounded sequential runtime.

Observe → decide → request or stop

Put policy selection in front of a text-only, non-streaming OpenAI-compatible backend that reports usage. Requests after STOP are never issued.

01 / FLIGHT RECORDER

A stop you can inspect.

The confidence-0.85 strategy waits for its minimum of two observations. When both parsed answers agree, vote confidence reaches 1.00 and the session stops at two of eight. Every remaining slot is explicitly marked as a request that was not issued.

02 / STRATEGIES

Choose the controller you can defend.

Start with the policy you can explain today; graduate only when validation supports it. Every strategy implements the same observed-prefix decision interface and honors a hard sample horizon.

01 / PREDICTABLE

Fixed count

Stop after an operator-selected number of samples. A transparent baseline and a dependable deployment default.

FixedStrategy(samples=2, max_samples=8)
02 / OBSERVABLE

Agreement rules

Stop on a vote-share threshold or a run of identical parsed answers. Decisions come directly from the observed prefix.

VoteConfidenceStrategy
ConsecutiveAgreementStrategy
03 / LEARNED

Safetensors policy

Distill exact offline stopping targets into a marginal-sample-cost-conditioned Q-policy. Deployment is Torch-free and the artifact is hash-bound and non-executable.

BranchPilotPolicy.load("policy.safetensors")
03 / GATEWAY

Keep the client. Change the control plane.

Run a text-only OpenAI-compatible gateway in front of a sequential upstream. The operator owns credentials, route limits, the deployment plan, and the decoding boundary.

  • STANDARD REQUESTPOST /v1/chat/completions
  • MODEL ALIASmath-local maps to the upstream model.
  • RESULT HEADERSx-branchpilot-samples, -strategy, and -selection.
Two processes + one standard client request 
# Credentials referenced by examples/gateway.json
export BRANCHPILOT_GATEWAY_KEY=client-secret
export BRANCHPILOT_UPSTREAM_KEY=upstream-secret

# Process 1 · vLLM environment; outside BranchPilot's install boundary
vllm serve Qwen/Qwen2.5-1.5B-Instruct --host 127.0.0.1 --port 8001 --api-key "$BRANCHPILOT_UPSTREAM_KEY"

# Process 2 · BranchPilot source environment
uv sync --extra gateway
uv run branchpilot-gateway --config examples/gateway.json --host 127.0.0.1 --port 8000

# Standard OpenAI-compatible request
curl -i http://127.0.0.1:8000/v1/chat/completions \
  -H "Authorization: Bearer $BRANCHPILOT_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"math-local","messages":[{"role":"user","content":"What is 17 + 25?"}]}'

# Illustrative response when the first two parsed answers agree
x-branchpilot-samples: 2
x-branchpilot-strategy: vote_confidence
x-branchpilot-selection: majority
04 / EVIDENCE

Negative results stay visible.

The canonical v0.2 benchmark tested the prespecified learned-policy criterion on one model and one task. That criterion failed. The result constrains the learned strategy; it does not erase the deployable fixed and heuristic controllers.

Canonical v0.2 FAIL

Learned policy did not beat its validation-frozen comparators.

Primary marginal-sample utility lower bounds were −0.0152, −0.0422, and −0.0491. The protocol required two strictly positive bounds and a third nonnegative bound.
